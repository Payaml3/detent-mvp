---
title: "Policies and rule versions"
description: "Your rules, as versioned YAML, changed only by two people."
---

Your **policy** is a rule set you own: a YAML document of checks, limits, deadlines and owners. Your sandbox
organisation starts with version 1 of the default rules; read them in the console's **Policy** screen or with
`GET /v1/policy/versions`.

```yaml
checks:
  kyb_status: {block_on: [failed, unknown], escalate_on: [pending]}
  allowlist: {escalate_if_not_listed: true}
  screening: {provider: mock, block_on_hit: true}
  travel_rule: {threshold: {USDC: "1000.00"}, required: [originator.name, beneficiary.name]}
  allowed_networks: {USDC: [base-sepolia, eth-sepolia], GBP: [banksim-fps], EUR: [banksim-sepa-inst]}
  limits:
    auto_limit: {USDC: "10000.00"}   # above -> ESCALATE
    hard_max:   {USDC: "100000.00"}  # above -> BLOCK
  daily_caps:
    platform: {USDC: "50000.00"}
    per_counterparty: {USDC: "20000.00"}
  unusual:
    new_wallet_days: 7
    changed_details_days: 14
    first_payment: escalate
    above_norm_multiplier: 3.0
  resubmission_after_block: {window_hours: 24, action: escalate}
deadlines:
  payout_above_auto_limit: PT2H
  payout_other: PT4H
```

## The checks

| Check | Result | Reason codes |
|---|---|---|
| Mandate (agent payouts) | BLOCK | `MANDATE_MISSING`, `MANDATE_EXPIRED`, `MANDATE_REVOKED`, `MANDATE_AMOUNT_EXCEEDED`, ... |
| KYB status | BLOCK or ESCALATE | `KYB_FAILED`, `KYB_PENDING` |
| User verified (user payouts) | ESCALATE | `USER_NOT_VERIFIED` |
| Allowlist | ESCALATE | `NOT_ALLOWLISTED` |
| Screening | BLOCK | `SCREENING_HIT` |
| Travel rule | ESCALATE | `TRAVEL_RULE_MISSING` |
| Allowed networks | BLOCK | `NETWORK_NOT_ALLOWED` |
| Auto limit and hard maximum | ESCALATE, BLOCK | `ABOVE_AUTO_LIMIT`, `ABOVE_HARD_MAX` |
| Daily caps | ESCALATE | `DAILY_CAP_PLATFORM`, `DAILY_CAP_COUNTERPARTY` |
| Unusual activity | ESCALATE | `NEW_WALLET`, `CHANGED_DETAILS`, `FIRST_PAYMENT`, `ABOVE_NORM` |
| Resubmission after a block | ESCALATE | `RESUBMISSION_AFTER_BLOCK` |

A payout to one of your own end users is decided under the user payout profile: KYB status, allowlist, first
payment, above norm and the per-counterparty daily cap are skipped, and `user_verified` runs instead. See
[Pay your own users](/guides/user-payouts).

## Changing the rules

1. Your payments lead or compliance lead drafts a change from the active version in the console.
2. The console shows a structured diff and marks any change that **loosens** the rules: a higher limit, a check
   removed, a wider network list, a shorter screening scope.
3. A second, different person approves it. Your compliance lead is one of the two on every activation, and attests.
4. The new version becomes active; the old one is kept as `superseded`. Nothing is deleted.

Payments already being decided keep the version they started with. Before anything is sent, the rules are checked
again with the active version, so a tightened rule still catches a payment approved under the old one.
